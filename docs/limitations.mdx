# Current limitations

Fulmetry favors explicit unsupported and incomplete results over broad claims. The most important current boundaries are summarized here; the repository README and product requirements remain the detailed authority.

## Availability

- The `fulmetry` and `create-fulmetry` registry packages are not published yet.
- The initial supported platform is Apple Silicon macOS with Bun 1.3.14 exactly.
- A pinned Apple Silicon macOS CI workflow exists, but the repository README records whether its live hosted-runner authority has been observed.

## Board scope

- One board per project.
- One rectangular two- or four-layer board for verified manufacturing.
- Supported component-owned SMT, circular or straight routed-slot component-owned PTH, NPTH, and full-stack through vias.
- Axis-aligned rectangular copper keepouts are checked independently on each declared board layer; other keepout shapes remain unsupported.
- Source-bound custom footprints require an explicit manufacturer part number and safe emitted geometry; explicitly marked mechanical support pads do not become electrical pins.
- Ownerless SMT pads and fiducials are not yet inside the verified promotion surface.
- Verified manifests are content-addressed but unsigned.

## Browser and 3D inspection

- The browser is a read-only inspection and derived-action surface; edits are made in project source.
- Schematic and PCB canvases are tscircuit-backed SVG views. Structured Circuit JSON and bounded inspection results remain authoritative.
- The 3D view reconstructs board, pad, trace, hole, and component primitives from available Circuit JSON geometry. It does not yet resolve vendor STEP/GLTF models, prove enclosure clearance, or become mechanical or manufacturing evidence.
- WebGL-unavailable machines retain the 2D and structured inspection surfaces and receive an explicit 3D fallback state.

## Tools

- Fulmetry does not install ngspice or KiCad.
- ngspice passage requires exact-executable qualification during the current run.
- KiCad 10 is the initial live-supported major; KiCad 9 is detection-only.
- Current converter output is known to produce KiCad ERC warnings, so a live interoperability fixture may correctly demonstrate an authenticated failed result rather than false passage.

## Sourcing and standards

- Live supplier search and authenticated provider/cache evidence are unimplemented.
- A source-authored component selection record proves reviewable selection integrity only; it does not establish availability, price, lifecycle, or package compatibility.
- Standards profiles beyond the local fabrication baseline and routing remain unimplemented.
- Profile evidence is not regulatory certification.

## Security and isolation

- Verified source checks reject known nondeterministic and runtime-I/O surfaces, but they are not a sandbox for malicious project source.
- Offline mode describes Fulmetry-managed work; it does not universally contain trusted code.
- Project tests and selected external tools are trusted executable inputs.

## Upgrade process

The initial release fixes the accepted tscircuit version. Maintainer upgrade and acceptance interfaces exist, but macOS refuses candidate execution until Fulmetry has a qualified native descendant-process broker. Ordinary authoring and inspection remain available with the pinned engine.
