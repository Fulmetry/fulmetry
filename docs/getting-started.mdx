# Getting started

Fulmetry is published to npm. This page covers the supported environment, the package flow for a new project, and how to work from the source repository as a contributor.

## Supported environment

The initial release authority is deliberately narrow:

| Requirement | Supported value |
| --- | --- |
| Operating system | macOS |
| Architecture | Apple Silicon (`arm64`) |
| Runtime | Bun 1.3.14 exactly |
| Circuit engine | The tscircuit version pinned by Fulmetry |

Unsupported Bun versions fail before project evaluation or authoritative output is published.

## Package flow

Start a new project with:

```sh
bun create fulmetry my-board
cd my-board
bun run build
```

This runs the published [`create-fulmetry`](https://www.npmjs.com/package/create-fulmetry) package and installs the framework, [`fulmetry`](https://www.npmjs.com/package/fulmetry), for you.

<Info>
Fulmetry is experimental. Manufacturing output must pass its explicit verification gates before any production use.
</Info>

## Work from the source repository today

Contributors can clone the implementation and install its locked dependencies:

```sh
git clone https://github.com/Fulmetry/fulmetry.git
cd fulmetry
bun install --frozen-lockfile
bun run fulmetry help
```

Check the repository before changing it:

```sh
bun run typecheck
bun run test:regular
```

Some live tests require separately installed and qualified tools. Fulmetry itself does not install KiCad or ngspice.

## Generated projects

The scaffold produces a normal single-package repository with:

- a multi-file circuit under `circuit/`;
- `fulmetry.config.ts` for resolved project configuration;
- deterministic `fulmetry.lock` authority;
- Bun tests;
- an agent guide;
- version-matched project-local Agent Skills under `.agents/skills/` and `.claude/skills/`; and
- scripts for build, check, inspection, simulation, and export.

The scaffold refuses to overwrite an existing path. Pass `--no-skills` to omit the skills. Existing projects can install the public catalog separately with `bunx --bun skills@latest add Fulmetry/fulmetry --copy` (or `npx skills@latest add Fulmetry/fulmetry --copy`); Fulmetry projects use copies because symlinks are rejected by the authoritative project-input boundary.
