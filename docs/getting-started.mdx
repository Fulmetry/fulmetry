# Getting started

PCBoo is published to npm. This page covers the supported environment, the package flow for a new project, and how to work from the source repository as a contributor.

## Supported environment

The initial release authority is deliberately narrow:

| Requirement | Supported value |
| --- | --- |
| Operating system | macOS |
| Architecture | Apple Silicon (`arm64`) |
| Runtime | Bun 1.3.14 exactly |
| Circuit engine | The tscircuit version pinned by PCBoo |

Unsupported Bun versions fail before project evaluation or authoritative output is published.

## Package flow

Start a new project with:

```sh
bun create pcboo my-board
cd my-board
bun run build
```

This runs the published [`create-pcboo`](https://www.npmjs.com/package/create-pcboo) package and installs the framework, [`@pcboo/pcboo`](https://www.npmjs.com/package/@pcboo/pcboo), for you.

<Info>
PCBoo is experimental. Manufacturing output must pass its explicit verification gates before any production use.
</Info>

## Work from the source repository today

Contributors can clone the implementation and install its locked dependencies:

```sh
git clone https://github.com/pcboo-dev/pcboo.git
cd pcboo
bun install --frozen-lockfile
bun run pcboo help
```

Check the repository before changing it:

```sh
bun run typecheck
bun run test:regular
```

Some live tests require separately installed and qualified tools. PCBoo itself does not install KiCad or ngspice.

## Generated projects

The scaffold produces a normal single-package repository with:

- a multi-file circuit under `circuit/`;
- `pcboo.config.ts` for resolved project configuration;
- deterministic `pcboo.lock` authority;
- Bun tests;
- an agent guide;
- version-matched project-local Agent Skills under `.agents/skills/` and `.claude/skills/`; and
- scripts for build, check, inspection, simulation, and export.

The scaffold refuses to overwrite an existing path. Pass `--no-skills` to omit the skills. Existing projects can install the public catalog separately with `bunx --bun skills@latest add pcboo-dev/pcboo --copy` (or `npx skills@latest add pcboo-dev/pcboo --copy`); PCBoo projects use copies because symlinks are rejected by the authoritative project-input boundary.
