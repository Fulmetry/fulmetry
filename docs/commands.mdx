# Commands

Run Fulmetry commands from a project containing `fulmetry.config.ts` and `fulmetry.lock`. Add `--json` when a coding agent will consume the result.

## Core commands

| Command | Purpose |
| --- | --- |
| `fulmetry build` | Compile twice and emit normalized Circuit JSON. |
| `fulmetry check` | Evaluate the implemented electrical and fabrication checks. |
| `fulmetry test` | Run eligible Bun tests and reconcile their result. |
| `fulmetry inspect` | Return bounded geometry, connectivity, status, or rule information. |
| `fulmetry dev` | Start the fixed local inspection server. |
| `fulmetry simulate [name]` | Run a named simulation through a qualified solver. |
| `fulmetry route freerouting` | Run the pinned, digest-authenticated Freerouting adapter and retain its output as a non-authoritative candidate. |
| `fulmetry route promote` | Convert an explicitly selected candidate into semantic TypeScript route modules in a fresh directory. |
| `fulmetry export kicad` | Create and validate a detached KiCad handoff. |
| `fulmetry export gerbers` | Emit an unmistakably draft manufacturing set. |
| `fulmetry verify manufacturing` | Independently parse and reconcile manufacturing artifacts. |

## Typical agent loop

```sh
bun run fulmetry build --json
bun run fulmetry check --json
bun run fulmetry inspect --status fabrication --json
bun run test
```

The compact terminal output is for humans. Versioned JSON is the stable automation surface.

Routing follows a candidate-and-promotion boundary. `route freerouting` requires an explicitly supplied Freerouting 2.2.4 JAR and SHA-256, Java 25, and bounded heap, thread, pass, element, and time limits. It never edits source. `route promote` is the only routing command that writes authored TypeScript; it writes a fresh directory, emits semantic endpoint selectors plus explicit via geometry, and refuses overwrite. A promoted route still has to pass Fulmetry's independent electrical and fabrication checks.

## Local inspection server

```sh
bun run fulmetry dev --port 0 --json
```

The server binds to `127.0.0.1` by default. On loopback it can expose same-origin, token-protected actions for build, check, and named simulation work. Those actions can write derived `.fulmetry` output but cannot edit authored circuit source or configuration.

The responsive browser workspace covers the project overview, schematic and PCB inspection, per-layer filtering, local 3D assembly review, checks, simulations, manufacturing output references, and searchable Circuit JSON. The structured API and source files remain authoritative.

Binding to a non-loopback host is explicit, produces a warning, and disables browser actions.

## Offline policy

Finite commands accept `--offline` and record the selected network policy. Fulmetry currently implements no network-backed resolver, so its own managed work remains local under both policies.

<Warning>
`--offline` is not a general operating-system sandbox for trusted project code. Circuit source or configuration that deliberately performs its own network access is outside that flag's claim.
</Warning>

## Run evidence

Every finite command writes its complete report to a fresh `.fulmetry/runs/<run-id>/report.json`. A command failure may leave isolated evidence for diagnosis, but incomplete or cancelled work cannot become authoritative browser state or a verified bundle.
